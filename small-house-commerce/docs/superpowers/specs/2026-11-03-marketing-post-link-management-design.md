- 后续交付边界：先做隔离的本地版供用户查看；本任务不授权推送、部署或修改生产数据。
- 核验基线：生产分支 `staging/luwag-shop-domain`，提交 `72711978e7fbafac274f59f61064b11ebf02c05b`。实施前仍须重新核验实际生产基线，不从当前旧的共享工作树盲目开工。

## 1. 背景、目标与边界

### 1.1 已确认的业务问题

同一商品会在不同日期、甚至同一天发布多条 Facebook 帖子：

1. 多帖共用同一个 `cl` 投放链接时，系统只能归因到该链接，不能自动拆分到具体帖子。
2. 每帖新建独立链接可以区分归因，但现有投放链接管理页是平铺列表，长期使用会越来越杂。
3. 核算页已有“商品 → 来源 → 链接”分组，但链接身份尚未明确展示为“发帖日期＋帖子名称”。

### 1.2 设计目标

**后台一商品一入口，追踪一帖子一链接，旧帖归档但不断归因。**

- 商品主列表不因同一商品每天发帖而不断增加行数。
- 可以快速为一条新帖子生成独立、可复制的投放链接。
- 可以查看具体帖子的人工登记日期、内容主题、原帖地址与现有核算结果。
- 旧链接、已有订单归因、现有统计口径及权限保持兼容。
- 不要求先取得 Facebook 帖子 ID，不增加“先发布才能生成链接”的限制。

### 1.3 方案选择

| 方案 | 评价 |
| --- | --- |
| 仅规范链接命名、增加日期筛选 | 开发少，但未解决主列表长期堆积；不作为本次主方案。 |
| 复用独立投放链接，新增商品收纳视图与帖子资料 | 本次采用；管理和核算共用同一个链接身份，不建立平行归因系统。 |

### 1.4 不在范围内

- 不接 Facebook / Meta Insights，不获取平台侧点击、覆盖、播放、赞评分享。
- 不做自动发帖、定时发布、素材库或跨平台内容管理系统。
- 不改变 7 天营销触达有效期、最后一次有效触达策略、凭证验签、事件幂等或订单归因快照。
- 不改 Pixel、CAPI、订单状态、费用核算公式、ERP 或物流集成。
- 不把混用旧链接的历史订单虚构拆分到各条帖子。
- 不改商品页、全局导航、Header、Footer、店面设计或商品分类/集合。
- 不删除原平铺视图，不新增侧栏导航项或独立一级后台模块。

## 2. 术语与不可变规则

| 名称 | 含义 |
| --- | --- |
| 商品汇总行 | 按现有 `productId` 动态计算的管理视图，不是新业务实体。 |
| 帖子记录 | `sourceType = FB_POST` 的一条现有 `CampaignLink`，附带可选发帖资料。 |
| 其他投放记录 | 现有 Meta 广告等非 `FB_POST` 链接；继续保留，不强行解释成 Facebook 帖子。 |
| 发帖日期 | 运营人工登记的日期，不是链接创建时间，也不是系统证明的 Facebook 发布时间。 |
| 原帖地址 | 可选的 Facebook 原帖 URL，用于回看，不承担归因身份。 |
| 归档 | 仅改变日常管理列表的收纳状态，不改变链接的有效性。 |
| 停用 | 沿用现有 `CampaignLink.status = DISABLED` 的业务规则，与归档相互独立。 |

不可变规则：

1. 每次“新增帖子”都创建新的 `CampaignLink.id` 与 `code`；即使商品、日期、名称相同，也不得复用上一条链接身份。
2. 名称、发帖日期、原帖地址均为可编辑资料；修改这些资料不能被当作新建帖子，也不能重置历史数据。
3. 分组收纳不能导致多条帖子共享同一个 `cl`。
4. 当前系统没有仅凭 Facebook 跳转、浏览器 referrer 或统计日期可靠识别具体帖子的能力；本次不宣称增加该能力。
5. 归因结果仍代表站内最后一次有效投放触达，不等同于 Facebook 官方归因报告；链接被转发后仍归属于原链接。

## 3. 投放链接页的管理体验

### 3.1 两个视图

仅投放工作台的主投放链接页新增视图切换：

- **按商品**：主页面默认视图。
- **全部链接**：保留原平铺列表及原有操作。

商品页、落地页等其他位置嵌入的链接列表继续保持原有平铺形态，不自动套用新主视图。

进入“按商品”时默认查看未归档记录；进入“全部链接”时默认查看全部归档状态。两个视图均明确显示当前归档筛选，不允许后台隐藏条件。切换视图重置分页，不重置商品、投放师、来源等已选业务筛选。

### 3.2 商品主列表

仅列出当前账号权限及当前筛选下确有投放记录的商品，不加载全目录空商品占位行。

每个商品只占一行：

- 复用现有商品缩略图、商品名称、商品编码。
- 匹配的投放记录数，以及其中的 Facebook 帖子数；不把广告链接也标为“帖子”。
- 最近登记的发帖日期；没有日期时显示“发布日期未登记”。
- “新增帖子”和“查看记录”操作。

计数、最近日期都基于当前完整筛选结果，而不是当前子列表分页。最近日期只取匹配的 `FB_POST.postDate` 最大值。

默认排序：最近发帖日期倒序、空日期在后；同值再按最近链接创建时间倒序、商品 ID 升序，保证翻页稳定。

商品分组独立分页，每页 20 个商品。不得先对链接分页，再把当前一页拼成不完整商品分组。

### 3.3 页级筛选

保留商品、投放师、链接状态、搜索；新增：

- 来源：沿用现有来源枚举，默认全部。
- 发帖日期：起止日期；另有“发布日期未登记”选项。
- 归档状态：未归档 / 已归档 / 全部。

权限没有 `VIEW_ALL` 时不提供跨投放师选择，服务端也不得接受越权查询。

搜索覆盖原有链接名称、AID、广告 ID、链接码，并支持商品名称/编码和已登记原帖地址。所有筛选先生成同一个可见链接集合，再计算商品汇总和子列表。搜索匹配商品名称时可以匹配该商品下的全部符合其他条件的链接；仅匹配某条链接名称时只计入匹配的链接。

发帖日期筛选与“发布日期未登记”只针对 `FB_POST`；启用后非帖子来源不参与结果。非 `FB_POST` 来源与帖子日期条件同时选择时返回明确的无效筛选提示，不静默忽略条件。“未登记”与日期范围互斥。

### 3.4 商品记录抽屉

点击“查看记录”打开现有后台风格的抽屉，不跳到新一级页面。

- 抽屉继承页级筛选，只额外固定当前商品 ID 并维护独立子分页；不出现另一套隐形筛选。
- 主要信息：发帖日期、名称、来源、投放师、链接状态、归档状态。
- `FB_POST` 有原帖地址时显示“打开原帖”，新窗口打开并设置 `noopener noreferrer`。
- 保留查看核算、费用、复制、重命名、复制新建、停用等现有能力；新增编辑帖子资料、归档、取消归档。
- “查看核算”使用该条真实链接 ID 过滤现有核算页。
- 每页 20 条；新视图按 `postDate DESC NULLS LAST, createdAt DESC, id ASC` 排序，未登记旧链接不会消失。
- 列表不预加载商品下的全部历史记录；父列表也不为每个商品发送额外子列表请求。
- 只读用户可以浏览及使用原有只读操作，但不能看到可执行的写入操作。

原平铺视图保留创建时间倒序的默认排序和现有分页规则。抽屉具备对话框语义、焦点约束、关闭后焦点恢复、键盘关闭和可访问的按钮名称。

## 4. 新增、编辑与复制帖子

### 4.1 新增流程

1. 从商品行点击“新增帖子”，锁定该商品，默认来源为 `FB_POST`。
2. 发帖日期默认菲律宾当天，名称留空时支持自动命名；可输入内容主题。
3. 保留现有目标商品页/落地页、变体选择与可选高级营销字段，不偷偷改变目标 SKU 或落地页。
4. 提交创建独立链接，成功后展示并允许复制；可继续为下一条帖子创建新记录。
5. 发帖后可以补原帖地址，不要求创建前提供。

没有投放记录的新商品仍可通过页面级“新增帖子”选择现有可创建商品。无法投放的商品按现有业务校验禁用新增，不因分组改版绕过限制。

### 4.2 日期、命名与来源

- `postDate` 使用 `YYYY-MM-DD` 日历日期；默认值通过 `Asia/Manila` 计算，不使用操作者设备所在时区的本地日期。
- 新的“新增帖子”界面要求填写日期；日期是人工登记资料，可更正，不代表已由平台核实发布，也不触发定时发布。
- 为兼容旧客户端，旧 API 调用省略帖子日期时仍可创建旧式链接，日期保持空值。
- 自动命名示例：`11-03｜收纳柜｜帖子 k3N8aQ`。使用新链接码的短标识辅助辨认，不引入严格连续流水号；名称最多 120 字符，完整 ID/code 才是唯一身份，短标识不作为唯一约束。
- 手填主题保持原有名称校验；不要求同商品或同一天的名称唯一。
- 现有其他来源仍可创建。选择非 `FB_POST` 时界面不展示帖子日期/原帖地址，恢复现有通用链接流程；非空帖子专属资料不得写入其他来源记录。

### 4.3 原帖地址

- 可选，允许发布后补录或清空，最长 2048 字符。
- 只接受可解析的 HTTPS URL，禁止 URL 用户名/密码。
- 主机必须为 `facebook.com`、其真实子域或 `fb.watch`；使用 URL hostname 校验，不使用字符串前缀判断，不能放行 `facebook.com.example.com`。
- 不请求 URL、不抓取页面、不解析跳转、不调用 Facebook API，不引入 SSRF 或额外凭据需求。
- 不要求从地址解析帖子 ID，也不以是否能解析 ID 判断链接有效性。

### 4.4 编辑与复制新建

- 编辑允许更新名称、日期、原帖地址；界面说明“修改资料不会创建新帖子”。
- 日期和原帖地址省略代表不改，显式 `null` 代表清空；名称不能清空。
- 编辑不改变链接码、归属投放师、来源、目标商品/变体/落地页、UTM/广告标识或历史事实表。
- 元资料按链接当前值展示，不回写订单归因快照。补录/更正日期后，历史结果会随该链接进入新的“发帖日期”筛选，这是资料更正，不是重新归因。
- “复制新建”必须生成新 ID/code；不继承旧原帖地址和归档状态。
- 新界面的复制流程把日期默认设为菲律宾今天，名称默认重新生成，主题可修改；`FB_POST` 克隆显式提供新日期但省略名称时，服务端使用新链接短标识自动命名。旧克隆客户端未提供新资料时，日期/原帖地址保留空值，名称沿用既有兼容行为，不暗中照抄旧帖日期。
- 克隆的原有归属及跨账号管理规则保持不变；普通新增仍按现有规则归属当前账号，不把商品汇总行或投放师筛选当作写入归属授权。
- 在他人投放师筛选下创建自己的记录时，不擅自替别人建记录；成功但不匹配当前筛选时明确提示并提供清除筛选入口。

### 4.5 短链与复制失败

复用现有 `POST /api/v1/admin/short-links`，发送 `{ url: 已创建链接的站内 path+query }`，完整保留 `cl` 和原有参数。不建立新的短链归因身份或统计系统。

- 创建成功后尝试缩短该条专属链接；相同目标路径复用现有短链去重。
- 返回短链 path 后，以当前可见站点 origin 拼接；本地使用本地地址，不拼生产域名，也不使用服务器内部 `0.0.0.0`。
- 短链失败时保留已创建记录，提供长链复制及“重试短链”。重试不得再创建一条帖子。
- 复制失败时保留结果，允许重试和手动选择，不把复制失败报告为创建失败。
- 使用已有复制兼容工具，不另写不兼容本地 HTTP 的复制路径。
- 创建按钮提交期间禁用；创建响应丢失时不自动重发创建请求，提示刷新列表核对，避免连续创建相同记录。本次不引入新的创建幂等子系统。

## 5. 归档、停用与历史记录

### 5.1 两个独立维度

| 链接状态 | 归档状态 | 效果 |
| --- | --- | --- |
| ACTIVE | 未归档 | 正常管理、正常建立新触达。 |
| ACTIVE | 已归档 | 从未归档视图收起，仍正常建立新触达。 |
| DISABLED | 未归档 | 保留可见，但沿用既有停用行为。 |
| DISABLED | 已归档 | 同时收起和停用；取消归档不等于重新启用。 |

- 归档只改服务端时间戳和版本号，不改 `status`、短链目标、订单、访问、事件或费用。
- 不按天数自动归档或停用，不新增“自动清理历史链接”。
- 核算默认包含归档记录，不因日常管理归档漏掉旧帖继续带来的结果。
- 现有停用会阻止该链接建立新的有效触达；已签发且未过期凭证的既有处理保持不变。本次不附加凭证撤销语义。

### 5.2 旧链接兼容

- 所有旧记录的新字段初始为 `null`；不把 `createdAt` 当作发帖日期，不自动归档。
- 旧链接、短链、签名凭证和既有订单归因持续兼容，不迁移/删除历史事实数据。
- 无日期的 Facebook 链接显示“发布日期未登记”，可以筛选和手工补录。
- 已共用于多帖的链接保持历史共用记录，不伪造一个精确发布日期；可通过现有名称改为“历史共用链接”识别，不新增未经证实的自动标签。
- 从新流程开始，一条新帖子使用新的独立链接；不承诺补录原帖地址后能恢复此前已混用链接的逐帖历史。

## 6. 核算页与日期语义

### 6.1 复用现有报表

继续使用“商品 → 来源 → 链接”的树，以及原平铺视图和指标列。仅在真实链接行的身份区域补充帖子日期、名称和原帖入口，不为商品/来源汇总行编造单一发帖日期。

- TREE 模式继续强制按 LINK 取底层数据，保留真实来源和链接名称。
- FLAT + LINK 行可展示资料；PAGE / PRODUCT / OWNER 汇总行的帖子资料为空。
- `otherSources` 没有已登记链接身份，不伪装成一条帖子。
- 链接 metadata 为附加字段，不改变现有指标类型与公式。

### 6.2 统计区间与发帖日期必须独立

| 条件 | 行为 |
| --- | --- |
| 原有 `from` / `to` | 访问按 `visit_day`、漏斗按 `event_day`；订单沿用既有触达 cohort 日期等核算事实口径，不改成统一下单日口径。 |
| 可选发帖日期范围 | 先筛选人工登记日期符合范围的 `FB_POST` 链接，再沿用上述统计区间计算指标。 |
| 可选“发布日期未登记” | 只选日期为空的已登记 `FB_POST` 链接，再使用原统计区间。 |

- 默认不设置发帖日期条件，因此旧帖子在当前统计区间内带来的结果仍可见。
- 页面明确标注“统计区间”和“发帖日期（仅 Facebook 帖子）”，不得把后者变成前者的隐形替代。
- 启用任一帖子日期条件时，无链接的其他来源无法判断发帖日期，不纳入该筛选结果；`otherSources` 返回空列表并显示“当前仅统计符合条件的已登记 Facebook 帖子链接”。取消条件后恢复原行为。
- 按发帖日期和链接筛选的条件必须同时应用到订单、费用、访问、事件、覆盖天数和树级去重查询的同一个链接集合，不允许父行和子行口径不一致。
- 商品/来源层访问沿用跨链接的 `COUNT(DISTINCT (visit_key, visit_day))`；不能简单加总每帖访问。事件次数、订单、金额和费用沿用既有聚合及覆盖规则，缺失分母/费用仍显示“—”。
- 发起结账等事件继续遵守原有会话去重规则；逐帖验收使用独立购物/结账会话，不为让每帖出现增量而重复发送事件。
- 加购/发起结账只能统计已有有效链接归因的事件；历史 `campaign_link_id` 为空的事件不回填，补录帖子资料不会凭空恢复历史漏斗数据。

## 7. 数据与接口合同

### 7.1 数据模型

只扩展现有 `CampaignLink` / `campaign_links`，不新增商品组、帖子归因表或第二套链接身份。

| 字段 | 数据库映射 | 含义 |
| --- | --- | --- |
| `postDate` | `post_date DATE NULL` | 人工登记发帖日期；输出为 `YYYY-MM-DD` 或 null。 |
| `postUrl` | `post_url VARCHAR(2048) NULL` | 可选 Facebook 原帖地址。 |
| `archivedAt` | `archived_at TIMESTAMPTZ(3) NULL` | 归档服务端时间；输出 ISO 时间或 null。 |

- 保留现有 `version` 作为并发控制，不增加独立版本字段。
- 添加 `(owner_user_id, archived_at, product_id)` 和 `(product_id, source_type, post_date)` 索引；保留现有索引。
- 迁移仅添加可空列及索引，无回填、无全表重建、无历史事实表迁移。
- 迁移后重新执行 Prisma generate；生成客户端遵循仓库现有忽略规则。不借本任务格式化其他 schema。
- 所有序列化器显式规范日期；不把 Prisma DATE 的午夜 ISO 字符串直接作为前端日历日期合同。

### 7.2 接口增量

以下路径均为现有 API 前缀 `/api/v1` 下的合同。

| 接口 | 新增/扩展行为 |
| --- | --- |
| `GET /admin/campaign-links/product-groups` | 新增商品分组查询；静态路由注册在 `:id` 路由之前。 |
| `GET /admin/campaign-links` | 增加帖子/归档筛选及可选排序；旧参数和默认创建时间排序继续兼容。 |
| `POST /admin/campaign-links` | 接收可选 `postDate`、`postUrl`；`FB_POST` 且日期非空时允许省略名称并自动命名，其他情况仍要求有效名称。 |
| `GET /admin/campaign-links/:id` | 附加返回帖子资料和归档时间。 |
| `PATCH /admin/campaign-links/:id` | 接收可选 `name`、`postDate`、`postUrl` 和必填 `expectedVersion`；至少一个可编辑字段。旧的仅改名请求保持可用。 |
| `POST /admin/campaign-links/:id/clone` | 接收可选新帖子资料；不得隐式继承旧日期、原帖地址或归档状态。 |
| `POST /admin/campaign-links/:id/archive` | 新增；仅 body `{ expectedVersion }`，归档时间由服务端决定。 |
| `POST /admin/campaign-links/:id/unarchive` | 新增；仅 body `{ expectedVersion }`，清空归档时间。 |
| `GET /admin/marketing/reports` | 增加可选帖子日期条件，真实注册链接行附加 `postDate`、`postUrl`、`archivedAt`；原统计条件和指标不变。 |
| `POST /admin/short-links` | 不改合同，复用现有缩短能力。 |

共有新增查询条件：

- `sourceType`：现有来源枚举；用于链接列表及商品分组。
- `archiveState = UNARCHIVED | ARCHIVED | ALL`：用于链接列表及商品分组。省略时 API 默认为 ALL，兼容旧客户端；新版界面显式传当前选项。
- `postDateFrom` / `postDateTo`：有效 `YYYY-MM-DD`，允许单边范围；同时存在时起始不晚于结束。
- `postDateMissingOnly`：布尔值，与任何帖子日期边界互斥。
- `orderBy = CREATED_AT_DESC | POST_DATE_DESC`：仅链接列表；省略保留原排序。

报表只增加上述帖子日期条件，不把管理页的归档状态隐式带入报表。发帖日期条件一旦启用，仅筛选已登记 `FB_POST`；与链接集合不匹配时返回空结果，不自行放宽条件。

分组响应为 `{ items, total, page, pageSize }`：每项包含现有商品摘要、`recordCount`、`postCount`、`lastPostDate`、`latestCreatedAt`。`total` 为匹配商品数，日期和计数基于分页前完整可见集合。列表每页默认 20，最大 100，不返回每组全量链接。

归档/编辑均沿用预期版本检查：过期版本返回 409，不覆盖其他人的修改；实际改变成功后版本加一。归档状态已经符合目标且预期版本仍匹配时返回当前记录，不额外加版本。不存在或不可见的链接沿用现有不可见资源处理。

### 7.3 权限、请求与错误

- 所有新增接口继续使用现有认证、MarketingGuard、VIEW_OWN / VIEW_ALL、MANAGE_OWN / MANAGE_ALL 检查；查看所有不等于管理所有。
- 权限范围必须在分组、计数、日期聚合、分页和搜索前生效；不能先全局计数再只隐藏行。
- 商品分组是只读聚合，不能赋予对其他投放师记录的写权限。
- DTO 保持严格校验，拒绝伪造 owner/code/archive 时间、非法日期、非法 URL、冲突筛选和越界分页。
- 查询继续参数化，不拼接用户 SQL；管理数据保持私有且不作公共缓存。
- 切换账号/权限范围后立即清空旧数据；取消旧请求或忽略乱序返回，不将旧账号结果闪回。一般筛选刷新可保留同权限范围旧内容，但必须显示更新状态和错误，不能把旧数据伪装为已加载新结果。
- 提交冲突保留用户输入，提示刷新后再提交；归档成功后同步更新抽屉和商品汇总。
- 不把营销凭证、token、生产配置或完整敏感请求载荷写日志。

## 10. 验收标准

### 10.1 核心场景

| 编号 | 场景 | 必须满足 |
| --- | --- | --- |
| A1 | 同商品不同日期发三帖 | 主列表仍只有一商品行，明细有三条不同 ID/code。 |
| A2 | 同日发布两帖，名称相同 | 仍是两个独立链接；界面可通过日期/名称/链接标识识别，不发生归因合并。 |
| A3 | 点击各帖链接并加购、进入结账 | 本地事件分别关联对应链接；核算各链接独立，父级访问保持跨链接去重。 |
| A4 | 同一用户先访问帖 A 后访问帖 B 再下单 | 沿用最后一次有效触达结果，不把本次功能误实现为多触点分摊。 |
| A5 | 昨天的帖子今天产生事件和订单 | 原统计区间/订单 cohort 口径不变；登记日期仍为昨天，不自动变成今天。 |
| A6 | 活跃旧帖归档后产生新访问/订单 | 默认未归档列表收起，但链接/短链继续可用；核算仍包含其结果。 |
| A7 | 停用后取消归档 | 不把停用链接重新启用，不额外改变既有有效凭证处理。 |
| A8 | 旧链接没有日期或曾被多帖共用 | 空日期保留，可查可用；不自动按创建日回填或虚构逐帖历史。 |
| A9 | 补录/更正日期与原帖地址 | 链接码和历史事实不变；日期筛选按更正后资料，原帖能安全打开。 |
| A10 | 克隆旧帖 | 生成新链接；不继承旧原帖地址、旧日期或归档状态，新界面默认今天。 |
| A11 | 普通投放师与只读用户 | 不泄漏他人计数/商品/链接；只读不能写；查看所有权限不自动赋予管理所有。 |
| A12 | 编辑或归档遇到版本冲突 | 409 且不覆盖新值，界面保留输入并提示刷新。 |
| A13 | 短链、复制失败或创建响应丢失 | 已创建记录不丢失，不自动重复创建；可按明确的重试/核对路径继续。 |
| A14 | 分页、搜索、筛选及乱序请求 | 商品计数完整稳定，抽屉条件一致，账号范围变化不闪回旧数据。 |
| A15 | 发帖日期过滤与其他来源 | 仅筛选已登记 Facebook 帖子；其他来源提示与实际响应一致，取消后恢复原数据。 |

### 10.2 证据要求

- 后端：DTO、权限、归档 CAS、克隆/编辑/序列化单测；真实 PostgreSQL 集成验证分组分页、完整计数、日期筛选、事件归属、跨链接访问去重及订单 cohort 不变。
- 前端：分组/平铺、筛选、抽屉分页、生成/编辑/复制、错误处理、权限切换与真实 TREE 无 `rows` 载荷回归测试。
