# 投放工作台与独立商品落地页设计

日期：2026-10-09
状态：业务方向及费用币种已确认；本文件待用户书面审阅，尚未进入实现计划。

## 1. 已确认的目标

优化师从母商品创建自己的展示副本，独立调整文案、图片、视频及详情结构，发布后生成可用于投放的链接，并关联访问、订单和广告花费。

用户已经确认：

- 展示内容采用独立副本，不随母商品更新自动覆盖；需要时手动同步。
- SKU、价格、库存与履约仍使用母商品的真实数据，不复制一套商品库存。
- 第一版包含广告花费、获客成本与 ROAS，不只统计订单数。
- 广告费以 USD 录入；订单仍是 PHP，需要保存换算汇率。
- FAQ 属于商品上架与商品编辑，单独设计，不迁移到投放后台。

完整业务流程为：选择母商品、创建草稿、编辑和预览、发布、创建投放链接、录入费用、查看归因与核算。不能只把原来的两个菜单放进同一个页面。

## 2. 现状与需修复的断点

- ProductLandingPage 目前只支持标题、图库、SEO、促销和时间窗口等覆盖；公开页面仍读取母商品的实时详情，不能形成独立的完整展示副本。
- 页面没有优化师负责人；编辑权限依赖 PRODUCT_MANAGE，普通 OPTIMIZER 无法管理自己的页面。
- CampaignLinkBuilder 只在浏览器拼网址，没有持久化投放链接，AID 由人工输入。
- tracking.ts 从当前地址读取投放参数，仅落地页 ID 单独持久化；从落地页跳到购物车和确认页后可能丢失广告参数。
- OrderAttribution 当前接受请求里的 optimizerId；新链路必须由服务端确定归属，而不是相信客户端填写的优化师 ID。
- 当前落地页统计主要是全生命周期统计；日期过滤作用于页面修改日期，不能冒充按投放期间核算。
- `optimizers`、`cost_entries` 在 DATABASE.md 中有逻辑规范，但尚无完整实现。签收不会自动更新 COD 回款，亦没有可据以计算净退款金额的账本。

## 3. 信息架构与工作区

### 3.1 投放工作台首页

统一业务入口名称为“投放工作台”，以落地页和投放链接为可关联的工作对象，提供“我的页面”“投放链接”“广告费用”“核算”四个视图。

OPTIMIZER 默认且只能看自己的记录；管理员可切换全部、负责人、母商品、页面及链接。按商品进入时自动带入母商品过滤条件。

页面列表显示：内部名称、母商品名称与 Product Code、负责人/AID、发布状态、未发布修改、链接数、所选期间访问及订单数、最后修改时间。动作包括编辑、预览、创建链接、查看核算、停用；创建时直接选择母商品并生成草稿。

页面修改时间过滤与核算日期过滤是两个不同条件，不能复用同一字段混淆语义。

### 3.2 完整编辑页

不继续使用承载所有内容的大弹窗。完整编辑页使用：

- 顶部固定状态栏：母商品、负责人、稳定公开地址、保存草稿、发布/更新发布、停用。
- 页面内容视图：左侧模块目录，中间手机/电脑预览，右侧选中模块的字段设置。
- 页面设置视图：内部名称、SEO、促销说明、启用状态和生效时间。
- 投放与核算视图：本页的链接、费用和归因结果，不另起一套重复表单。

编辑预览明确标识“未发布内容”；查看线上版本另开已发布页面，不能把草稿预览伪装成线上结果。

### 3.3 链接与费用的关联

页面行中“创建投放链接”自动带入母商品、页面和负责人。链接行中直接进入费用及核算，费用录入自动带入链接，避免反复重选同一组数据。

允许针对同一页面创建多条链接，分别表示广告活动、广告组或素材。也保留直接投母商品及指定有效规格的能力，不强迫所有投放都先复制页面。

## 4. 复制哪些内容，哪些内容保持实时

| 独立展示快照 | 母商品实时真相 |
| --- | --- |
| 展示标题、tagline、营销正文、促销文案 | 商品与 SKU 身份、有效规格及可售状态 |
| 图库、详情图片/视频、说明文字 | 当前价格、库存、购买限制与履约规则 |
| 可编辑模块的排列与显示配置 | 真实评论、商品规格事实及商品 FAQ |
| 页面 SEO 与首屏宣传内容 | 站点 Header/Footer、联系设置和交易流程 |

- 来源仅限母商品已保存的内容，不读取另一位操作者未保存的 ProductForm。
- 独立图库沿用现有媒体类型与作用域语义；引用的选项值/款式 ID 仍属于母商品，不允许营销编辑器创建或改写 SKU。
- 母商品规格停用或删除后，对应购买选项不可售；不能偷偷替换成另一个规格自动下单。失效的展示绑定显示可诊断提示，并不破坏其他有效选项。
- 购买区块必须恰好一个，SKU/价格/库存字段不可改写；复用现有购买、购物车、COD 确认及下单链路。
- 评论与 FAQ 可配置呈现位置，但内容由商品域提供。营销页面不提供评论造假、Verified Purchase 编辑或 FAQ 文案编辑。
- 不夹带 Header/Footer 编辑、首页外壳设置、Bundle 重构或优惠券系统。

## 5. 编辑器选型与安全边界

选择 Puck 作为受控 React 组件编辑器，而不是独立 HTML 网站生成器。登记本项目的商品模块，复用现有前台组件、样式变量与媒体上传能力；不引入整套 Payload/Directus 后台。

截至调研时，`@puckeditor/core` 0.23.0 为 MIT，peerDependencies 支持 React 18/19。书面设计批准后，实施计划的首项验证其在现有 Next 16/React 19 上的客户端加载、iframe 预览、编辑和发布渲染；验证不通过则停止并回报，不静默更换技术路线。

拟新增依赖：前端 `@puckeditor/core`；后端富文本净化使用成熟的 `sanitize-html`，不手写正则 HTML 过滤器。依赖安装须在实施计划获准执行后进行；需验证运行时满足所选包的 Node 要求。

受控模块包括营销首屏、图库、购买区、营销正文、详情媒体、商品事实、评论与商品 FAQ。编辑器只登记这些模块，不开放任意代码、脚本、iframe、全局 CSS 或外部请求表达式。

保存的是验证过的编辑文档 JSON，不把导出 HTML 当成编辑真相。模块 ID 在文档内唯一；来源标识也必须唯一，复制来源区块时新副本转为自定义区块，不复用来源标识。富文本由后端按标签、属性、协议白名单净化，公开页与预览使用同一净化结果；链接限 http/https/mailto，媒体接受现有 http(s) 地址及单斜杠 `/uploads/...` 路径，拒绝 `//host`、javascript 和 data 脚本地址。

文档最多 60 个顶层模块、512 KiB，单段富文本最多 20 KiB，媒体地址最多 2,048 字符；复用已有文件大小、格式和上传并发限制，不绕开正在优化的上传生命周期控制。

## 6. 草稿、发布与手动同步

### 6.1 两份内容，独立保存

ProductLandingPage 增加 `ownerUserId`、`draftContent`、`publishedContent`、`version`、`publishedRevision`、`publishedAt`、`sourceContentHash` 等字段。

- 新建页面默认 DRAFT，无公开已发布内容。
- 保存草稿仅更新编辑数据，不修改顾客正在看到的 publishedContent。
- 发布在一个事务中验证文档、母商品状态与版本锁，再把草稿复制为已发布快照，增加发布版本。
- 已发布页面继续编辑后仍保持原页面上线，显示“有未发布修改”。
- ACTIVE 页面仍需处于生效窗口且母商品 ACTIVE，才能公开访问；DISABLED、未发布、未生效或已结束均不泄露草稿。
- 保存及发布使用 `expectedVersion`；冲突返回具名 409，保留用户草稿，不强行覆盖。
- slug 创建后不可变；改内部名称或营销标题不改变公开地址。

V1 保存当前草稿和当前已发布内容，不实现无限版本历史或 A/B 自动分流。访问和订单保存当时的发布版本号，避免把新文案误认为历史投放内容。

### 6.2 手动同步母商品

内容指纹仅覆盖可复制的展示字段，不因母商品价格或库存变化就提示“展示内容过期”。

母商品展示内容变化后仅显示提醒。操作者进入同步比较，选择要替换的来源区块，确认后只更新草稿。区块带稳定来源标识，替换保持原排列，不删除用户额外加入的营销区块；被移除的来源区块重新导入时需显式选择插入位置。

不做自动三方合并，也不自动发布同步结果。同步不会修改母商品，不会复制或覆盖价格、库存、评论或 FAQ 数据。

## 7. 优化师身份与权限

新增与现有 User 一对一关联的 OptimizerProfile，包含内部 ID、userId、唯一 AID、展示名和 ACTIVE/DISABLED。AID 是优化师身份，不是广告 ID、广告组 ID或页面内部名称。

- 创建链接时由服务端从当前账号或管理员明确选择的负责人获取 AID；优化师不能手填他人的 AID。
- 新页面、链接和费用均明确保存 ownerUserId。沿用现有 orders.optimizerId/OrderAttribution.optimizerId 列时，新链路写关联 User.id，而不是把 OptimizerProfile.id 偷换进旧列；需在实施中同步规范这一映射。
- 已生成 AID 不随姓名修改而变化。新建营销身份时生成稳定唯一代码，既有旧代码只有经管理员确认后才能登记，不能按姓名猜测。
- 新页面负责人创建后固定；负责人变更通过复制为新页面处理，不把原链接、费用和历史订单整体搬给另一个人。
- 账号停用禁止新的后台操作，不隐式停掉正在投放的页面。停投必须明确停用页面或链接。

权限分为 MARKETING_VIEW_OWN、MARKETING_MANAGE_OWN、MARKETING_VIEW_ALL、MARKETING_MANAGE_ALL；OPTIMIZER 默认获得 own，ADMIN/SUPER_ADMIN 获得 all，FINANCE 默认仅获得全量核算读取能力，不自动获得页面编辑权。

所有查询、统计、详情及写操作在服务端按权限与 ownerUserId 限定；越权资源返回 404，拒绝通过列表总数、费用或汇总结果泄露他人数据。旧营销入口不能保留绕开该范围检查的服务分支。

优化师可查看归因订单号、商品、金额、时间及状态，不因此获得客户手机、地址、订单改价或客服操作权限。完整订单详情仍遵守原订单权限。

## 8. 持久化投放链接

新增 CampaignLink：内部 ID、不可猜的公开 code、ownerUserId、目标母商品、可选有效规格、可选落地页、内部名称、来源类型、campaign/adset/ad ID、UTM 配置、状态和创建时间。

- 服务端验证产品、规格、落地页三者关联正确，并在自己的页面范围内创建。
- 保存后生成 `/lp/<slug>?cl=<code>` 或现有商品地址附加 `cl` 的网址；UTM、Facebook 点击参数可以继续存在，但负责人不能被网址里的另一个 aid 覆盖。
- 负责人、目标、来源类型和核算归因字段创建后固定。需要另一广告/目标时复制生成新链接；内部名称和停用状态可以改。
- 链接与有访问、费用或订单历史的页面不硬删除；停用用于停止新投放。
- 停用链接不清除停用前已经有效发生的触达，不倒改已创建订单快照。
- 预览地址不作为投放地址，不允许为未发布页面生成可投放链接。

## 9. 从访问到订单的可靠归因

### 9.1 服务端确认触达

新增公开营销触达接口：浏览器上报 `cl` 或实际落地页身份及会话标识，服务端验证目标和可访问性、确定归属与来源，记录有效访问，再返回有签名、有效期明确的归因凭据。

凭据只用于营销归因，不是管理员登录 token。签名带用途隔离，使用既有服务端秘密派生专用用途密钥；不引入另一套生产环境凭证，不把签名密钥下发前端。

- 来自链接的归属与广告元数据取 CampaignLink，不相信客户端传入的 optimizerId。
- 无 `cl` 的已归属落地页可记录 DIRECT 页面来源，但不自动伪造成某条付费投放链接。
- 旧链接上的 AID 仅在已有明确登记映射时解析归属，标记为 legacy 来源；未知 AID 留为未明确归属，不能自动创建优化师。
- legacy 页面/链接来源不能猜测归入新 CampaignLink 的广告费核算。
- 无效或停用的新触达不阻止顾客正常浏览与购买，也不覆盖此前仍有效的归因凭据；带无效 `cl` 的访问不能降级伪装成一次新的 DIRECT 落地页触达。
- 下单时没有有效凭据就不分配新的营销归属；不从失败凭据或订单请求里的 owner/AID/optimizerId 猜测恢复归属。旧网址在新版浏览器链路中先取得经服务端确认的 legacy 凭据再参与归因。

### 9.2 跨页面保留

采用最后一次有效投放/落地页触达，设计默认窗口为 7 天。凭据保存期限及触达时间由服务端确定；浏览器保留凭据，使其贯穿页面、购物车、checkout、确认和提交，普通无参数页面不会清空归因。

有效的新营销触达可以替换旧触达；普通浏览不续期。过期凭据不再获得优化师/投放链接归属。关闭未保存的操作预览不改变客户归因。

归因是订单级：一张订单只归一个最终有效触达，整单金额只计算一次，包含同一购物车的其他商品；母商品字段表示投放入口商品，不冒充订单中每个商品的收入分配。

订单事务验证凭据并写入不可变快照：User/AID/名称、链接 ID、来源、活动参数、落地页 ID及发布版本、触达时间。后续改名、停投或页面再次发布不重算历史快照。旧请求中的 optimizerId 不作为新链路身份依据。

### 9.3 访问与预览

链接访问按链接＋浏览器标签页会话＋马尼拉日期去重；同日刷新不重复计数，次日可形成新的有效访问。页面访问按页面＋同一会话＋日期独立去重，因此一个页面的访问数不等于其多个链接访问数相加。

触达日期来自服务端时钟。预览、草稿编辑器、后台测试和服务端 HTML 抓取不触发营销访问，未执行 JS 的访问不计入该口径。报表明确写“按日/会话去重访问”，不宣称人数或反作弊认证流量。

## 10. USD 广告费用

沿用 DATABASE.md 的 cost_entries 逻辑，V1 只开放 ADS_COST、MANUAL 广告费用，不提前实现采购、运费、佣金或退款成本系统。

每条记录绑定一个 CampaignLink 和一个马尼拉业务日期，保存 USD 金额、`phpPerUsd` 汇率、服务端计算的 PHP 金额、备注、负责人及操作者。每链接每天一条记录，再次录入是明确编辑，不重复追加费用。

- USD 金额最多两位小数且非负，日期不能晚于马尼拉今天，也不能早于链接创建业务日。
- 正金额要求正汇率，界面明确“1 USD = X PHP”；汇率最多六位小数。
- PHP 金额由服务端 Decimal 运算并逐条四舍五入到分，不能接受客户端提交的折算总额。
- 零费用可明确标记“当天未投放”，金额为零时不要求汇率；未录入与显式零费用不是一回事。
- 保存当时汇率，不查询当前汇率重新计算历史数据；更正金额或汇率必须是可审计的显式编辑。
- 使用版本锁避免两个人覆盖同一天费用；创建、修改和撤销记录保留操作者及前后值。撤销记录保留历史，不删除其审计轨迹。
- 不支持负数广告平台返款、自动拉取 Meta 费用、批量文件导入或自动汇率服务。

## 11. 核算时间与公式

### 11.1 日期口径

采用触达日期 cohort：选定的日期范围筛选当时发生的有效访问与触达；归因到这些触达的订单随后确认、发货或签收，仍回到该投放期间，不按签收日期挪进另一个广告费周期。

广告费按所选链接的同一业务日期范围汇总。CPA、ROAS 及其订单数、金额分子只包含这些已登记 CampaignLink 的归因结果；DIRECT、legacy 与未明确归属来源在总览单独展示，不能把免费来源的成交混入付费链接回报。所有界面业务日期为 Asia/Manila，时间戳存 UTC，费用业务日为 DATE。

历史旧订单或访问缺少可验证触达时间/链接的，单列为历史来源统计，不伪装成可核算 cohort。相同订单在链接、页面、优化师各层均只算一次；页面总访问独立去重。

范围内尚有未录入费用的日期时，显示费用覆盖情况，ROAS/CPA 数值为 `—`，标明“费用未完整录入”，已录入费用合计仍可查看；没有费用记录或费用合计为零时比值也为 `—`，不显示无穷大或零成本。链接创建前日期不要求补费用；未投放日期需要显式零费用记录才能区分。

### 11.2 指标

- 提交订单：该触达的全部已创建订单。
- 有效订单：排除当前 CANCELLED/DENIED；重复或风险标记不自动删单，另行提示。
- 确认订单：确实发生过确认且未取消/拒绝，不能只按当前状态恰好 CONFIRMED 查询。
- 签收订单：存在真实签收记录；AFTER_SALES 和支付退款状态另外列示，不伪造已完成退款金额。
- 有效下单金额：有效订单 grandTotal 的 PHP 合计。
- 签收毛额：真实签收订单的 PHP grandTotal 合计，包含整单运费，尚未扣退款，不等于已回款。
- 广告费：USD 合计及保存汇率折算后的 PHP 合计。
- 下单 CPA：USD 广告费 / 有效订单数。
- 签收 CPA：USD 广告费 / 真实签收订单数。
- 下单 ROAS：有效下单金额 PHP / 广告费 PHP。
- 签收 ROAS：签收毛额 PHP / 广告费 PHP。
- 转化率：有效订单数 / 所选统计层级的去重访问；不把每个 SKU 当一次订单，不用静默封顶掩盖重复购买。

订单数为零时相应 CPA 为 `—`，访问为零时转化率为 `—`。例如费用 USD 50、汇率 57.3，折算 PHP 2,865；签收毛额 PHP 10,000 时签收 ROAS 为约 3.49，不将 USD 50 直接除 PHP 收入。

报表固定标注“签收毛额未扣退款、不等于 COD 回款”；无退款金额账本时不显示净收入、净利润、佣金结算或 Profit ROAS。近期 cohort 标注“转化仍可能继续发生”，不能称为已经结清的账期。

## 12. 数据和接口边界

新增/扩展的后端对象包括 OptimizerProfile、CampaignLink、链接去重访问、页面去重访问日期、广告费用及其窄范围审计、页面草稿/发布快照、订单归因快照扩展。

后端接口按商品读取投影、营销页面、链接、费用和报告分别组织，复用同一 owner 约束。编辑器不会直接更新 Product、Sku 或库存表，报告不会通过浏览器拼接全部优化师数据再过滤。

公开查询只返回已发布展示内容、实时商品投影和可公开的来源标识。私有预览走受保护路径，设置 no-store/no-referrer，不接受公开 `/lp` 上一个任意 preview 参数来暴露草稿。

保存草稿不触发公开版本更新；发布、停用和母商品实时数据变化复用现有再验证机制。公开页与预览共用展示渲染组件，不维护两套不同的 DOM 逻辑。

## 13. 旧页面与链接保留

- 保留现有 `/lp/<slug>`；原 `/admin/single-pages` 与 `/admin/link-builder` 入口进入新的对应工作视图，保留可理解的商品筛选条件。
- 旧页面迁移时按当时公开效果生成发布快照：既有覆盖优先，未覆盖的营销展示字段取母商品。生成相同草稿，初始效果不随意重排。
- 旧页没有明确负责人时保持“历史未分配”，仅管理员可编辑。管理员可以给未分配页面明确指定负责人，不倒改历史订单或费用归属。
- 不根据页面标题 MA-1、姓名、广告编号或任意旧 URL 猜测优化师。
- 旧参数网址继续可打开；已有明确登记的 AID 可解析，未知来源明确标注，不制造新归属。
- 不清除历史访问和订单快照，也不把全生命周期旧统计包装成新广告费用周期统计。

迁移为加性，但会冻结旧页面展示内容并涉及身份、归因和费用，因此不能作为无需确认的普通前端热修直接部署。部署前须验证迁移效果、旧链接、回滚边界及当时真实生产状态。

## 14. 验收与门禁

### 内容和编辑

复制不会改母商品；母商品文案变更不自动覆盖副本，价格/库存实时变化仍生效。覆盖媒体支持站内上传地址。草稿不可公开、保存不影响线上、发布原子更新、版本冲突不丢用户输入，手动同步只改选定草稿区块。验证既有规格媒体、购买、购物车和 COD 确认流程。

### 权限和安全

两个真实优化师账号互相不能读取或修改页面、链接、费用及统计；管理员可以跨账号管理，财务只能读取其许可范围。篡改 owner/AID/optimizerId、cl 与目标产品关联、凭据签名或用途不得产生伪造归属。预览不能泄露或计数，恶意富文本不能执行。

### 归因

浏览真实公开链接，经过商品、集合、购物车、checkout 和 confirm 后下单，数据库仍保存原链接与优化师快照。验证新有效触达覆盖、普通浏览不覆盖、7 天过期、链接停用后的既有触达、重复提交只创建一张订单、混合商品购物车和未登记旧 AID。

### 核算

验证按日去重、页面/链接去重区别、延后签收仍属于原 cohort、零值/缺费用、Decimal 汇率、跨马尼拉日期边界、费用重复与并发更正、撤销审计、售后/退款状态标记、历史来源隔离和聚合不重复计单。

### 完成条件

TDD 回归测试、实际部署基线的全量单元测试、类型检查、lint、构建和隔离数据库浏览器 E2E 均完成；不能用 mock 保存代替真实后端归因验证。生产冒烟不擅自创建广告费、评论或订单，不轮换管理员登录状态。

## 15. 实施次序与明确排除

后续实施计划按身份/权限和数据基础、展示副本编辑与发布、链接及归因、费用与报表、旧数据迁移和端到端验收安排依赖；商品 FAQ 独立接入，两项数据库迁移串行执行。

只在书面设计、实施计划及执行方式批准后写产品代码、安装依赖或迁移数据库。保留当前本地商品/首页优化与评论图片热修，不通过 reset、stash 或整分支部署绕开并行工作。

V1 不包含广告平台自动同步、净利润/退款/佣金账本、自动 A/B 分流、拖入任意脚本、完整 CMS 更换或生产旧数据归属猜测。
